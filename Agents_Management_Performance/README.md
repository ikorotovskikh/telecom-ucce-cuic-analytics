# Agent_Management_Performance (УО по операторам)

## Overview
A comprehensive historical performance report for contact center agents, capturing inbound metrics, manual outbound dialing sequences, and automated outbound dialer campaign lifecycles. 

The report implements an advanced data-flattening database architecture designed to consolidate records across asynchronous platform subsystems with built-in arithmetic exception defense layout logic.

## Technical Metadata
* **Data Source Architecture:** `STAT_DB` via optimized cached staging tables `#TCL` (`tContactLog`) and `#TCD` (`t_Termination_Call_Detail`).
* **Intermediate Translation Layer:** Formulates an in-memory session bridge tracking table `#TT` to reconcile dialer activity strings against core switching channels.
* **Organizational Mappings:** Resolves operational alignment variables through configuration entities `t_Agent`, `t_Agent_Team_Member`, and `t_Agent_Team`.

## Technical Calculations & Data Relationships

### 1. Telephony Log Timezone Offset Compensation (`#TCD` Ingestion)
Because the core switching database registers transaction markers under Greenwich Mean Time (UTC), an explicit 3-hour modification adjusts the selection parameters to match the localized timezone of the operational branches (MSK / UTC+3):
```sql
WHERE DATEADD(HOUR, 3, StartDateTimeUTC) >= @BeginDate 
  AND DATEADD(HOUR, 3, StartDateTimeUTC) <= @EndDate
```

### 2. Multi-Subsystem Cross-Engine Handshaking (`#TT` Cache Mapping)
As automated outbound dialer applications (`#TCL`) write logs independently from core switching tables (`#TCD`), the query establishes a temporary bridge cache table `#TT` via an advanced text-normalizing multi-token strategy:
* **Trailing 10-Digit Normalization:** Minimizes formatting prefix variances (e.g., country codes `+7`, `7`, trunk code `8`) by verifying only the rightmost 10 characters using a strict binary collation key restriction:
  ```sql
  RIGHT((CAST(CL.PhoneNumber AS varchar(32)) COLLATE Cyrillic_General_BIN), 10) = RIGHT(TCD.ANI, 10)
  ```
* **CRM Account Context Matching:** Cross-references the customer identifier token (`CL.ContactId`) against the platform's peripheral variable slot 4 (`TCD.Variable4`), heavily guarded by an inline format numeric validator check:
  ```sql
  CL.ContactId = CASE WHEN ISNUMERIC(TCD.Variable4) = 1 THEN CAST(TCD.Variable4 AS int) ELSE 0 END
  ```
* **Asynchronous Time Drift Buffer (2-Second Window):** Incorporates a dual-edge temporal adjacency barrier constraint to compensate for server clock synchronization drifts between dialer application nodes and peripheral ICM nodes:
  ```sql
  DATEADD(SECOND, -2, CL.ClientCallDialingEndTime) <= MIN(DATEADD(SECOND, -1*Duration, DateTime))
  AND DATEADD(SECOND, 2, CL.AgentCallDistributedTime) > MIN(DATEADD(SECOND, -1*Duration, DateTime))
  ```

### 3. Inbound Traffic Leg Isolation Formula
To capture true inbound traffic while ignoring consultative connections, internal employee desk loops, or transferred automated legs, the query evaluates specific type parameters and routing variable constraints inside `InboundCallsCalc`:
```sql
WHERE PeripheralCallType IN (2,3,4,5,6,12) 
  AND (Variable1 != 'Исходящий' OR Variable1 IS NULL) 
  AND TalkTime > 0
```

### 4. High-Performance Dataset Flattening Framework (`UNION ALL` Strategy)
To optimize processing speeds across large transactional tables and avoid row-dropping anomalies caused by standard `LEFT JOIN` operations on multi-conditioned subqueries, the query employs a vertical data consolidation pipeline:
* Implements independent Common Table Expressions (CTEs) to isolate metrics scopes: `NumCallsCalc`, `NumAttemptsCalc`, `AgentTimeCalc`, `ManualOutCallsCalc`, and `InboundCallsCalc` using 0-padded mask structures.
* Merges the blocks via a high-performance `UNION ALL` collection script, passing them to an outer statement.
* Compresses the records using a single `GROUP BY tm.EnterpriseName, AgentSkillTargetID, a.EnterpriseName` clause to generate one comprehensive performance line per operator.
* **Arithmetic Division Protection:** All calculated averages and ratios include inline `CASE WHEN denominator = 0 THEN 0` handlers to safeguard Cisco CUIC grid presentation layers against arithmetic division errors and dashboard execution crashes.
